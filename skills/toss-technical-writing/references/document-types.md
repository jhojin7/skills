# 문서 유형 정하기

기술 문서는 독자가 문서를 찾은 목적에 따라 유형을 나눌 수 있어요. 같은 기술을 다루더라도 독자가 배우고 싶은지, 문제를 해결하고 싶은지, 정확한 값을 확인하고 싶은지에 따라 문서의 구조와 내용이 달라져요.

문서의 주제보다 독자가 지금 하려는 일을 기준으로 유형을 선택하세요.

## 학습 중심 문서

새로운 기술이나 작업 흐름을 처음 접한 독자가 직접 따라 하면서 익히고 싶을 때 사용해요. 튜토리얼이나 시작하기 문서가 여기에 속해요.

### 권장 구조

1. 학습 목표
2. 사전 준비 사항
3. 가장 단순한 성공 경로
4. 단계별 실습
5. 최종 결과 확인
6. 자주 발생하는 문제
7. 다음에 배울 내용

### 체크리스트

- 독자가 문서를 끝까지 따라 하면 무엇을 할 수 있는지 먼저 알려주세요.
- 처음에는 성공할 가능성이 높은 좁은 경로를 안내하세요.
- 예제 코드는 실제로 실행할 수 있어야 해요.
- 간단한 예제부터 시작해서 점진적으로 난이도를 높이세요.
- 각 단계에서 무엇을 하고 왜 하는지 설명하세요.
- 깊은 배경 설명이 실습 흐름을 끊는다면 별도 문서로 연결하세요.

## 문제 해결 문서

독자가 기술이나 도구를 어느 정도 알고 있고, 특정한 작업을 완료하거나 문제를 해결하고 싶을 때 사용해요.

### 작업 방법을 안내하는 문서

특정한 결과를 얻기 위한 방법을 안내할 때 사용해요. How-to 문서가 여기에 속해요.

#### 권장 구조

1. 목표
2. 사전 조건
3. 작업 절차
4. 결과 확인
5. 다른 환경이나 선택 사항

### 오류를 해결하는 문서

에러나 비정상적인 동작의 원인을 찾고 해결할 때 사용해요. 트러블슈팅 문서가 여기에 속해요.

#### 권장 구조

1. 증상 또는 정확한 에러 메시지
2. 영향을 받는 환경
3. 가능한 원인
4. 원인을 확인하는 방법
5. 해결 방법
6. 해결 여부 확인
7. 해결되지 않았을 때의 다음 단계

### 체크리스트

- 독자가 겪는 문제나 달성하려는 결과를 구체적으로 쓰세요.
- 안전하고 빠르게 확인할 수 있는 방법부터 안내하세요.
- 원인을 확인하는 과정과 문제를 고치는 과정을 구분하세요.
- 각 해결 방법이 어떤 상황에 적용되는지 설명하세요.
- 문제가 해결됐을 때 나타나는 정상적인 결과를 알려주세요.

## 참조 문서

독자가 시스템의 기본 사용법을 알고 있고, API, 함수, 옵션, 반환 값처럼 정확한 정보를 빠르게 확인하고 싶을 때 사용해요.

### 권장 구조

1. 개요와 사용 조건
2. 구문 또는 시그니처
3. 매개변수, 속성, 옵션
4. 반환 값 또는 출력
5. 오류와 제한 사항
6. 사용 예제
7. 관련 API

### 체크리스트

- 처음부터 끝까지 읽는 글보다 필요한 정보를 찾는 문서로 구성하세요.
- 같은 종류의 항목은 같은 순서와 형식으로 작성하세요.
- 타입, 기본값, 필수 여부, 단위, 버전 범위를 알 수 있다면 함께 쓰세요.
- 중요한 제한 사항을 긴 문장 안에 숨기지 마세요.
- 예제는 가장 기본적인 사용법부터 보여주세요.

## 설명 문서

독자가 개념이 왜 등장했고 어떻게 동작하는지 깊이 이해하고 싶을 때 사용해요.

### 권장 구조

1. 개념 소개
2. 등장 배경과 해결하려는 문제
3. 동작 원리
4. 장점과 단점
5. 다른 방식과 비교
6. 실제 활용 사례
7. 한계와 주의 사항

### 체크리스트

- 독자가 이미 알고 있는 개념에서 시작하세요.
- 비유를 사용할 때는 실제 동작과 비유를 구분하세요.
- 다이어그램이나 예제가 이해를 줄여준다면 사용하세요.
- 사용 절차만 나열하지 말고 동작 원리를 설명하세요.
- 장점만 보여주지 말고 선택할 때 고려할 점도 알려주세요.

## 여러 유형을 함께 사용할 때

독자의 목표가 하나의 유형만으로 설명하기 어렵다면 다른 유형의 요소를 일부 사용할 수 있어요. 다만 중심 유형은 하나로 유지하세요.

예를 들면 다음과 같이 구성할 수 있어요.

- 튜토리얼 안에 짧은 개념 설명을 넣어요.
- 작업 방법 문서에서 자세한 API 참조 문서로 연결해요.
- 트러블슈팅 문서에서 원리를 설명하는 별도 문서로 연결해요.

여러 유형의 전체 구조를 한 페이지에 모두 넣기보다, 필요한 문서를 나누고 링크로 연결하는 편이 독자가 정보를 찾기 쉬워요.
