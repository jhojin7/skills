# 정보 구조 만들기

문서를 읽는 사람의 입장에서 정보를 배치하세요. 기술 문서는 주로 문제를 해결하거나, 새로운 내용을 배우거나, 정확한 정보를 찾기 위해 사용해요. 독자가 어떤 목표로 문서를 찾았는지 생각하면 필요한 정보와 순서를 정하기 쉬워져요.

## 한 페이지에서는 하나만 다루세요

한 페이지에서는 하나의 핵심 목표만 다루는 것이 좋아요. 여러 목표가 섞이면 독자가 자신에게 필요한 내용을 찾기 어렵고, 문서를 수정할 때도 관련 내용을 빠뜨리기 쉬워요.

다음과 같은 경우에는 문서를 나누는 것을 고려하세요.

- 두 섹션이 서로 다른 독자의 목표를 해결해요.
- 제목 깊이가 `####` 이상으로 내려가요.
- 제목이 너무 넓어서 실제로 다루는 작업을 알기 어려워요.
- 한 주제를 수정해도 다른 주제는 함께 수정할 필요가 없어요.

관련된 여러 페이지를 소개해야 한다면 개요 페이지를 만들고, 각 페이지로 연결하세요.

## 제목에 핵심 내용을 담으세요

제목은 독자가 문서를 검색하고 빠르게 훑어볼 때 가장 먼저 확인하는 정보예요. 제목만으로 문서의 주제나 작업을 이해할 수 있어야 해요.

### 체크리스트

- 독자가 검색할 가능성이 높은 핵심 키워드를 포함하세요.
- 작업, API, 개념, 정확한 에러 중 무엇을 다루는지 드러내세요.
- 같은 수준의 문서는 제목 형식을 일관되게 사용하세요.
- 느낌표나 물음표보다 평서문이나 행동을 나타내는 제목을 사용하세요.
- 필요한 정확성을 해치지 않는 범위에서 30자 안팎으로 간결하게 쓰세요.

### 예시

- `NOT_FOUND_USER 오류 해결하기`
- `React 컴포넌트 만들기`
- `fs.readFile options 참조`

## 개요를 빠뜨리지 마세요

제목 바로 아래에 문서의 핵심을 설명하는 개요를 넣으세요. 독자는 개요를 읽고 이 문서가 자신의 상황에 맞는지 판단할 수 있어야 해요.

개요에서는 다음 질문에 답하세요.

- 이 문서를 읽으면 무엇을 할 수 있나요?
- 어떤 상황에서 이 문서가 필요한가요?
- 어떤 제품, 버전, 환경을 다루나요?

기술의 역사나 내부 구조보다 독자가 얻을 수 있는 결과를 먼저 알려주세요. 배경 설명이 꼭 필요한 사전 지식이 아니라면 뒤쪽에 배치하세요.

## 가치를 먼저 제공하세요

기능과 설정을 나열하기 전에, 그 기능으로 어떤 문제를 해결할 수 있는지 설명하세요.

다음 순서로 정보를 배치하면 독자가 핵심 내용을 빠르게 이해할 수 있어요.

1. 얻을 수 있는 결과
2. 사전 조건
3. 핵심 작업이나 설명
4. 결과 확인
5. 선택 사항, 다른 방법, 배경 정보

## 예측 가능한 구조를 사용하세요

같은 유형의 문서는 섹션 이름과 순서를 일관되게 유지하세요. 독자는 한 문서에서 익힌 구조를 다른 문서에서도 그대로 사용할 수 있어요.

예를 들면 다음과 같아요.

- 트러블슈팅 문서: `증상 → 원인 → 확인 → 해결 → 검증`
- API 문서: `개요 → 시그니처 → 매개변수 → 반환 값 → 오류 → 예제`

같은 개념을 여러 표현으로 바꾸지 마세요. 문장을 다양하게 쓰는 것보다 독자가 같은 개념이라는 것을 바로 알아보는 것이 중요해요.

## 필요한 순서대로 자세히 설명하세요

독자가 앞에서 얻은 정보를 사용해서 다음 내용을 이해할 수 있도록 순서를 정하세요.

1. 핵심 개념이나 목표
2. 기본 사용법
3. 구체적인 예제
4. 더 복잡한 동작
5. 예외 상황과 경계 조건

선택 사항이나 드물게 발생하는 예외가 기본 흐름을 끊는다면 문서 뒤쪽이나 별도 페이지로 옮기세요.
