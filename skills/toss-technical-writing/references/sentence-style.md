# 문장 다듬기

기술 문서는 정확하고 이해하기 쉬워야 해요. 독자가 문장을 여러 번 읽거나 앞뒤 문맥을 추측하지 않아도 바로 행동하고 결과를 확인할 수 있도록 작성하세요.

## 문장의 주체를 분명하게 하세요

문서에 적힌 작업을 직접 하는 사람이 독자라면, 독자가 무엇을 해야 하는지 중심으로 설명하세요.

### 좋은 예시

- `설정을 저장한 후 서버를 다시 시작하세요.`
- `이 명령어를 실행하면 데이터베이스를 초기화할 수 있어요.`

도구나 기술의 실제 동작을 설명할 때는 시스템을 주체로 사용할 수 있어요. 누가 행동하는지보다 문장이 설명하려는 실제 동작을 기준으로 판단하세요.

## 능동형으로 표현하세요

수동형 문장은 행동의 주체를 숨기고 문장을 길게 만들 수 있어요. 독자가 직접 해야 하는 작업은 명령형이나 능동형으로 쓰세요.

- `설정이 완료되어야 합니다.` → `설정을 완료하세요.`
- `변경 후 다시 빌드되어야 합니다.` → `변경한 후 다시 빌드하세요.`

## 한 문장에는 하나의 생각만 담으세요

조건, 행동, 결과가 한 문장에 여러 개 들어가면 문장을 나누세요. 서로 분리할 수 없는 하나의 작업일 때만 한 문장으로 묶으세요.

핵심 내용에 영향을 주지 않는 메타 담화는 줄이세요.

- `앞서 설명했듯이`
- `이제 알아보겠습니다`
- `결론적으로`
- `아시다시피`

## 명사보다 동사를 사용하세요

`수행`, `진행`, `처리`, `실시`처럼 동작을 명사로 표현하면 문장이 길고 모호해질 수 있어요. 독자가 해야 하는 행동을 동사로 직접 쓰세요.

- `배포 수행이 필요합니다.` → `배포하세요.`
- `설정 변경을 진행합니다.` → `설정을 변경합니다.`
- `인증 처리가 완료된 후` → `인증한 후`

## 구체적으로 쓰세요

독자가 문맥을 추측하지 않도록 알고 있는 정보를 구체적으로 쓰세요.

- 누가 행동하는지
- 무엇을 바꾸는지
- 어디에 적용하는지
- 어떤 방법을 사용하는지
- 어떤 환경이나 버전에 해당하는지
- 어떤 조건이나 수치를 기준으로 하는지
- 어떤 파일 경로, 명령어, 옵션, 에러를 확인하는지

구체적인 정보가 없을 때 임의의 수치나 환경을 만들지 마세요. 확인이 필요한 부분은 `TODO: 기준 확인`처럼 표시하세요.

## 자연스러운 한국어 표현을 사용하세요

영어식 명사형 표현이나 불필요하게 긴 한자어를 자연스러운 동사로 바꾸세요.

- `API를 통해 데이터를 가져옵니다.` → `API로 데이터를 가져옵니다.`
- `모니터링 수행을 통해 성능을 측정합니다.` → `모니터링해서 성능을 측정합니다.`
- `설정이 적용되어집니다.` → `설정이 적용됩니다.`

기술 식별자와 고유한 이름은 자연스러운 문장으로 바꾸지 말고 그대로 유지하세요.

## 용어를 일관되게 사용하세요

기술 용어는 공식 문서의 표기와 대소문자를 따르세요. 같은 개념은 한 문서 안에서 같은 표현을 사용하세요.

### 체크리스트

- 제품, 라이브러리, 언어 이름의 공식 표기를 사용했나요?
- 같은 개념을 여러 동의어로 바꾸지 않았나요?
- 약어가 처음 나올 때 필요한 전체 이름을 함께 썼나요?
- 프로젝트에 용어집이 있다면 그 기준을 따랐나요?
- 코드, 명령어, 경로, API 이름, 에러 메시지, UI 문구를 그대로 유지했나요?

## 확실한 내용과 추측을 구분하세요

확인된 동작만 단정적으로 쓰세요. 보장되는 동작, 일반적으로 나타나는 동작, 특정 조건에서 가능한 동작, 아직 확인하지 않은 가설을 구분해야 해요.

`일부 환경`, `문제가 생길 수 있어요`처럼 조건을 숨기는 표현보다, 알고 있는 환경과 조건을 직접 쓰세요. 조건을 모른다면 확인이 필요하다는 사실을 밝혀주세요.
