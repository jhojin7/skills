# 기술 문서 검토하기

문서를 검토할 때는 문장부터 고치지 마세요. 독자의 목표와 문서 유형이 맞는지 먼저 확인하고, 정보 구조와 문장을 차례로 살펴보세요. 앞 단계의 문제일수록 독자가 문서를 사용하는 데 더 큰 영향을 줘요.

## 1. 문서 유형을 확인하세요

다음 조건을 모두 만족하는지 확인하세요.

- 독자가 해결하려는 문제나 달성하려는 목표가 분명해요.
- 선택한 문서 유형이 독자의 목표와 맞아요.
- 해당 문서 유형에 필요한 내용이 들어 있어요.
- 다른 목적을 위한 내용은 별도 섹션이나 문서로 분리돼 있어요.

### 중요하게 고쳐야 하는 문제

- 튜토리얼이 독자에게 가르쳐야 할 내용을 이미 알고 있다고 가정해요.
- 트러블슈팅 문서에 정확한 증상이나 해결 여부를 확인하는 방법이 없어요.
- 참조 문서의 매개변수나 제한 사항이 긴 설명 안에 숨어 있어요.
- 설명 문서가 동작 원리를 설명하지 않고 작업 순서만 나열해요.

## 2. 정보 구조를 확인하세요

다음 조건을 모두 만족하는지 확인하세요.

- 한 페이지에서 하나의 핵심 목표를 다뤄요.
- 제목에 검색할 수 있는 주제나 작업이 들어 있어요.
- 개요에서 독자가 얻을 수 있는 결과와 문서 범위를 알 수 있어요.
- 부가적인 배경보다 독자가 얻을 수 있는 가치를 먼저 보여줘요.
- 같은 수준의 제목이 일관된 형식을 사용해요.
- 기본 흐름이 예외 상황이나 선택 사항 때문에 끊기지 않아요.
- 제목 깊이가 `###`을 넘지 않아요.

### 중요하게 고쳐야 하는 문제

- 문서를 끝까지 읽어야 자신의 상황에 적용되는지 알 수 있어요.
- 서로 다른 목표를 가진 내용이 한 페이지에 섞여 있어요.
- 사전 조건이 그 조건을 사용하는 단계보다 뒤에 나와요.
- 같은 개념을 섹션마다 다른 용어로 표현해요.

## 3. 문장을 확인하세요

다음 조건을 모두 만족하는지 확인하세요.

- 누가 무엇을 하는지 분명해요.
- 필요한 곳에서 능동형을 사용해요.
- 한 문장에 하나의 핵심 생각이 들어 있어요.
- 불필요한 명사형 표현을 동사로 바꿨어요.
- 주장하는 내용에 구체적인 조건과 범위가 있어요.
- 번역체가 아닌 자연스러운 한국어를 사용해요.
- 공식 용어와 약어를 일관되게 사용해요.

### 중요하게 고쳐야 하는 문제

- 문장을 고치면서 기술적인 의미가 달라졌어요.
- 생략된 주체나 모호한 지시어 때문에 여러 의미로 해석할 수 있어요.
- 제공된 자료에 없는 수치나 보장 내용을 추가했어요.
- 코드, 식별자, 경로, 명령어, API 이름, 에러 메시지, UI 문구가 바뀌었어요.

## 검토 결과를 작성하세요

문제점만 검토해 달라는 요청에는 다음 형식을 사용하세요.

```markdown
## 핵심 판단

[독자에게 미치는 영향과 전체적인 판단을 1~3문장으로 설명하세요.]

## 수정할 내용

### 문서 유형

- [문제 → 독자에게 미치는 영향 → 수정 방법]

### 정보 구조

- [문제 → 독자에게 미치는 영향 → 수정 방법]

### 문장

- [문제 → 독자에게 미치는 영향 → 수정 방법]

## 수정 예시

[전체 수정 요청을 받았거나 짧은 교체 문장이 필요할 때만 작성하세요.]
```

독자에게 영향을 주는 문제만 남기세요. 같은 원인에서 생긴 여러 증상은 하나의 문제로 묶어서 설명하세요.
