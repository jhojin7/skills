# 한국어 기술 문서 작성하기

기술 문서는 독자가 문제를 해결하고 목표를 이루도록 도와야 해요. 문서를 작성할 때는 작성자가 알고 있는 내용을 모두 보여주기보다, 독자가 필요한 정보를 빠르게 찾고 바로 적용할 수 있도록 구성하세요.

제공된 자료에 없는 동작, 수치, 사전 조건, 명령어, 제한 사항을 임의로 만들지 마세요. 확인할 수 없는 정보는 그럴듯하게 채우지 말고 `TODO`로 표시하세요.

## 1. 문서의 목표와 유형을 정하세요

먼저 다음 내용을 확인하세요.

- 독자가 이 문서를 읽고 해결하려는 문제나 달성하려는 목표
- 독자가 이미 알고 있는 내용
- 문서에서 다룰 제품, 버전, 운영체제, 실행 환경
- 가장 적합한 문서 유형

문서 유형은 [`references/document-types.md`](references/document-types.md)를 참고해서 정하세요. 문서 주제가 아니라 독자의 목적을 기준으로 선택해야 해요.

한 문서에서 여러 유형을 사용할 수 있지만, 중심이 되는 유형은 하나만 정하세요. 독자의 목표가 서로 다르다면 한 문서에 섞기보다 문서를 나누고 링크로 연결하는 편이 좋아요.

정보가 일부 부족해도 안전하게 작성할 수 있다면, 필요한 가정을 최소한으로 밝히고 계속 작성하세요. 사실을 확인해야 하는 부분은 `TODO: 확인할 내용`처럼 표시하세요.

### 완료 기준

- 독자가 달성할 목표를 한 문장으로 설명할 수 있어요.
- 문서의 중심 유형을 하나로 정했어요.
- 문서에 영향을 주는 환경과 범위를 확인했어요.

## 2. 정보 구조를 만드세요

[`references/information-architecture.md`](references/information-architecture.md)를 참고해서 문서 구조를 설계하세요.

- 한 페이지에서는 하나의 핵심 목표만 다루세요.
- 제목 바로 아래에 문서의 목표와 범위를 설명하는 개요를 넣으세요.
- 기능이나 배경보다 독자가 얻을 수 있는 가치와 결과를 먼저 보여주세요.
- 사전 조건, 핵심 내용, 실행 방법, 확인 방법, 부가 정보 순서로 배치하세요.
- 같은 유형의 문서는 제목과 섹션 순서를 일관되게 유지하세요.
- 제목 깊이가 `####` 이상이 되면 문서를 나누는 것을 고려하세요.

문서를 처음부터 끝까지 읽지 않아도 필요한 부분을 빠르게 찾을 수 있어야 해요. 독자가 어디에서 어떤 정보를 찾을지 예측할 수 있도록 제목과 구조를 만드세요.

### 완료 기준

- 각 페이지의 목표가 하나로 정리돼 있어요.
- 제목만 읽어도 문서의 주제나 작업을 알 수 있어요.
- 제목 깊이가 `###`을 넘지 않아요.
- 사전 조건이 필요한 단계보다 먼저 나와요.

## 3. 문서를 작성하거나 고치세요

[`references/sentence-style.md`](references/sentence-style.md)를 참고해서 문장을 작성하세요.

- 누가 무엇을 하는지 분명하게 쓰세요.
- 수동형보다 능동형을 사용하세요.
- 한 문장에는 하나의 생각만 담으세요.
- `수행`, `진행`, `처리`, `실시` 같은 명사형 표현보다 동사를 사용하세요.
- 모호한 표현 대신 실제 동작, 환경, 경로, 버전, 조건을 구체적으로 쓰세요.
- 공식 기술 용어와 대소문자를 따르세요.
- 같은 개념은 같은 용어로 표현하세요.
- 약어는 독자에게 필요하다면 처음 나올 때 전체 이름을 함께 쓰세요.

절차를 설명하는 문서에서는 다음 내용을 확인하세요.

- 명령어와 예제 코드를 실제로 실행할 수 있어요.
- 각 단계에서 무엇이 바뀌는지 알 수 있어요.
- 단계가 끝났는지 확인하는 방법이 있어요.
- 선택 사항과 예외 상황이 기본 흐름을 방해하지 않아요.

코드, 식별자, 명령어, API 이름, 에러 메시지, 파일 경로, UI 문구는 기술적인 오류가 확인되지 않았다면 그대로 유지하세요.

### 완료 기준

- 필요한 모든 단계에 확인할 수 있는 결과가 있어요.
- 문서에 있는 사실은 제공된 자료로 확인할 수 있어요.
- 확인할 수 없는 내용은 `TODO`로 표시했어요.
- 기술적인 이름과 값이 원문과 다르게 바뀌지 않았어요.

## 4. 세 단계로 검토하세요

[`references/review-rubric.md`](references/review-rubric.md)를 참고해서 다음 순서로 검토하세요.

### 1. 문서 유형 확인하기

독자의 목표와 문서 유형이 맞는지 확인하세요. 필요한 내용이 빠졌거나 다른 목적의 내용이 섞이지 않았는지 살펴보세요.

### 2. 정보 구조 확인하기

독자가 문서의 적용 범위를 빠르게 판단하고, 필요한 정보를 예상한 위치에서 찾을 수 있는지 확인하세요. 기본 흐름이 배경 설명이나 예외 상황 때문에 끊기지 않아야 해요.

### 3. 문장 확인하기

문장의 주체와 행동이 분명한지, 문장이 짧고 구체적인지, 자연스러운 한국어와 일관된 용어를 사용하는지 확인하세요.

독자에게 미치는 영향이 큰 문제부터 고치세요. 같은 원인에서 생긴 문제는 여러 항목으로 반복하지 말고 하나로 묶어서 설명하세요.

### 완료 기준

- 중요한 문제를 모두 고쳤어요.
- 고치지 못한 문제는 이유와 필요한 결정을 명확하게 남겼어요.
- 문장을 고치면서 기술적인 의미가 바뀌지 않았어요.

## 5. 결과를 전달하세요

### 문서를 작성하거나 전체적으로 고쳐 달라는 요청

1. 완성된 문서를 먼저 보여주세요.
2. 설명이 필요할 때만 짧은 `검토 메모`를 덧붙이세요.
3. 검토 메모는 독자에게 미치는 영향이 큰 순서로 최대 5개만 작성하세요.

### 문제점만 검토해 달라는 요청

1. 요청하지 않은 전체 수정본을 만들지 마세요.
2. 문제를 `문서 유형`, `정보 구조`, `문장`으로 나눠서 설명하세요.
3. 중요한 문제에는 바로 적용할 수 있는 수정 예시를 함께 보여주세요.

자료 안에서 서로 충돌하는 내용이 발견되면 하나를 임의로 선택하지 마세요. 충돌하는 내용을 밝히고, 어떤 확인이나 결정이 필요한지 설명하세요.
